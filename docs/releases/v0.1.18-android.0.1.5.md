Windows 0.1.18 и Android 0.1.5 — общий релиз. Обновляется Android; файлы Windows сохранены с прежними контрольными суммами.

### Android

- Журнал с телефона показал причину обрывов прямого трафика: Яндекс правильно получал маршрут «напрямую», но соединение по IPv6 через Wi-Fi завершалось `network is unreachable` или таймаутом. Клиент объявлял IPv6 в туннеле и возвращал IPv6-адреса DNS независимо от доступности такого маршрута.
- Теперь туннель Android по умолчанию использует IPv4, а DNS согласован с ним: обычные сайты остаются напрямую, сайты и приложения из VPN-правил — через VPN. Существующие правила, подписки и выбранный сервер сохраняются.
- В Настройки → Подключение добавлен «IPv6 в туннеле». Включайте его при работающем IPv6 в обычной сети и на сервере; настройка применяется с переподключением. Сайты только с IPv6 требуют её включения.
- Отключённый IPv6 блокируется Android внутри области действия VPN, чтобы не обходить туннель. Не выбранные приложения вне туннеля используют собственную сеть. Подключение к самому VPN-серверу сохраняет отдельное разрешение имени с поддержкой IPv4 и IPv6.

### Скачать

- **Android 10+:** один `Bebekon-Android.apk`, подписанный прежним ключом. Обновление из приложения либо установка поверх старой версии сохраняет данные.
- **Windows:** прежние Setup 0.1.18 и Portable ZIP; обновления Windows в этом релизе нет.
- Контрольные суммы и исходники ядра для обычного запуска скачивать не нужно.

### Проверки

52 модульных теста прошли. В настоящем Android VpnService проверены прямой HTTPS-запрос из общего туннеля и сайт через VPN, ответы DNS A/AAAA, немедленная блокировка соединения по IPv6, выбор приложений, веб-приложения, потоки, переподключение и отмена повторных попыток. Точная сессия Яндекса на физическом телефоне недоступна для воспроизведения: после обновления нужно подтвердить результат на устройстве.
