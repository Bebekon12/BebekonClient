# Маршрутизация Windows и Kill Switch

Профиль выбирает Bebekon VPN, NetBird, Direct или Block. Защищённые системные правила имеют приоритет. В каждой группе сохраняется порядок правил. Служба выбирает первый доступный VPN из списка резервов. Если все узлы недоступны, выбирается Block.

Имена серверов управления и сигнализации NetBird берутся из статуса клиента. Для зарегистрированной в Windows службы Bebekon направляет DNS-запросы к этим точным именам через основной интерфейс. Сам транспорт службы тоже проходит через основной интерфейс. Так вход в NetBird возможен, когда правило для корпоративных доменов уже действует, а корпоративный туннель ещё не поднялся.

Для системной защиты укажите IP/CIDR или полный путь к исполняемому файлу. Доменное правило с системной защитой требует выбрать приложения. Защита охватывает весь трафик указанных исполняемых файлов. Отдельные доменные правила для других приложений продолжают применяться в ядре sing-box.

Служба устанавливает фильтры WFP перед открытием туннеля. Сохраняемая политика начинает действовать после загрузки Base Filtering Engine. Её можно снять на странице «Защита» или с помощью команды `Bebekon.Service.exe --clear-leak-protection` от администратора.

## Проверки

- Диагностика правила сверяет его область с установленными фильтрами и имитирует потерю разрешённого пути на loopback. Для успеха нужны событие WFP с идентификатором фильтра и успешная проба после отката. Прогон loopback прошёл для TCP и UDP на IPv4 и IPv6. Отдельный тест проверил сохраняемую политику.
- Анализ маршрута работает с черновиком. Сетевая проба использует действующую конфигурацию. Проверка NetBird привязывает DNS и TCP к подтверждённому интерфейсу.
- Для приёмки корпоративной сети можно снять два состояния через `scripts/get-windows-routing-state.ps1`. Сравниваются маршруты, DNS и NRPT с подключённым NetBird до и после подключения Bebekon. Команда `Bebekon.Service.exe --test-netbird <домен или IP> [TCP-порт]` показывает подтверждённые реквизиты пробы. Приёмка конкретной корпоративной конфигурации остаётся открытой.

Привилегированные сценарии в изолированной Windows входят в `scripts/test-wfp.ps1 -PersistenceFixture` и в проверку перед публикацией релиза. Перезагрузку Windows, смену интерфейса и маршрутизацию стороннего приложения проверяют на отдельном стенде.
